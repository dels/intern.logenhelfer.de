# Product

## Register

product

## Users

Officers, secretaries, and members of a Freemason lodge organization (lodges,
districts) managing rosters, events, announcements, and prospective-member
("Seeker") vetting. Users range widely in age and technical comfort — this is
not a tech-forward audience by default. Usage is task-focused: look up a
member, check an event, review a Seeker file, publish an announcement — often
in short sessions, sometimes on a phone.

## Product Purpose

A member-management system (German: "Logenhelfer") replacing ad-hoc
spreadsheets/paper processes for lodge administration: rosters, officer
roles, events (internal + external/ICS-imported), file libraries by
category/directory, announcements, and a public calendar. Success is officers
trusting the data and finding what they need without training.

## Brand Personality

Formal, discreet, trustworthy — reflecting a private fraternal organization
handling sensitive membership data. Calm and orderly, not flashy or
"startup." Confidence through clarity and restraint, not decoration.

## Anti-references

Not a consumer SaaS dashboard with bright gradients, playful illustrations,
or marketing-style hero sections. Not dense enterprise-grid software that
prioritizes information density over readability — this audience skews
older and the content is sensitive, so clarity beats cramming.

## Design Principles

- Clarity over density — one primary action/read per view, generous
  whitespace over cramming.
- Restraint over decoration — the existing blue/gold palette signals
  institutional trust; new color should extend it, not compete with it.
- Comfortable, not clever — legible type sizes, calm motion, predictable
  navigation; this is a tool used by non-technical members, not a showcase.
- Sensitive-by-default — this system holds private roster/vetting data;
  visual design should never imply casualness about that (see CLAUDE.md's
  security requirements).

## Accessibility & Inclusion

WCAG 2.2 AA as the floor for all proposals (≥4.5:1 body text, ≥3:1 large
text/UI components, visible focus indicators, no color-only signaling).
Given the older/mixed-technical-comfort user base, prefer contrast and type
size comfortably above the AA minimum where it doesn't fight the brand
palette, rather than designing exactly to the line.
